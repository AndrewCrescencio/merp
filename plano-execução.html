Plano de Execução — Remoção de docs:* + Hardening Docker

Documento único para consumo por agente de código (Cursor, Claude Code, Copilot, Aider). Executar em ordem. Pedir confirmação antes de cada passo destrutivo.

0. Instruções gerais ao agente

Regra de ouro: não apagar nada de forma irreversível. Sempre listar, mostrar, pedir confirmação, aplicar, validar. Nada de rm -rf cego.
  • Não reformatar arquivos inteiros — editar apenas linhas afetadas.
  • Manter ordenação alfabética em package.json (scripts e devDependencies).
  • Não tocar em nuxt.config.ts, drizzle.config.ts, tsconfig.json nem código da aplicação, exceto onde explicitamente indicado.
  • Ao final de cada parte, rodar pnpm format nos arquivos alterados e mostrar git diff.
  • Se algo não estiver claro, perguntar antes de agir.

1.6 Procedimento de execução

  1. Listar (sem editar) todos os pontos acima e mostrar ao usuário.

  5. Rodar pnpm lint, pnpm typecheck, pnpm test.
  6. Rodar pnpm format nos arquivos alterados.
  7. Mostrar git diff --stat e resumo final.

Parte 2 — Hardening Docker + Hadolint

Hadolint ≠ markdownlint. Hadolint linta Dockerfile. Markdownlint linta .md. Este plano trata apenas do Hadolint.

2.1 Dockerfile — versão ajustada

Objetivo: pinar versão do pnpm, criar usuário não-root com UID/GID explícitos, --chown no COPY final, HEALTHCHECK.

# syntax=docker/dockerfile:1.7

# ---- Base ----
FROM node:24-alpine AS base

RUN corepack enable \
 && corepack prepare pnpm@10.18.0 --activate

WORKDIR /app

COPY package.json pnpm-lock.yaml* ./

# ---- Build ----
FROM base AS build

ARG CORS_ORIGIN
ENV CORS_ORIGIN=${CORS_ORIGIN}

RUN pnpm install --frozen-lockfile

COPY . .

RUN pnpm build

# ---- Production ----
FROM node:24-alpine AS production

RUN addgroup -g 1001 -S appgroup \
 && adduser  -u 1001 -S appuser -G appgroup

WORKDIR /app

COPY --from=build --chown=appuser:appgroup /app/.output /app/.output

ENV NODE_ENV=production
ENV PORT=3000

USER appuser

EXPOSE 3000

HEALTHCHECK --interval=30s --timeout=5s --start-period=20s --retries=3 \
  CMD node -e "fetch('http://127.0.0.1:3000/').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"

CMD ["node", ".output/server/index.mjs"]

Ajustar pnpm@10.18.0 para a versão realmente usada. Ajustar path do healthcheck se não houver / respondendo 200.

2.7 Como rodar o Hadolint

Via Docker (recomendado)

docker run --rm -i hadolint/hadolint < Dockerfile

Vários Dockerfiles

find . -name 'Dockerfile*' -not -path './node_modules/*' \
  -exec sh -c 'docker run --rm -i hadolint/hadolint < "$1"' _ {} \;

Local (se instalado)

brew install hadolint    # macOS
scoop install hadolint   # Windows
hadolint Dockerfile

2.8 Scripts opcionais no package.json

"lint:docker": "docker run --rm -i hadolint/hadolint < Dockerfile",
"lint:docker:all": "find . -name 'Dockerfile*' -not -path './node_modules/*' -exec sh -c 'docker run --rm -i hadolint/hadolint < \"$1\"' _ {} \\;"

Parte 3 — Ordem de execução

  1. Rodar Parte 1 completa. Confirmar lista, aplicar, pnpm install, validar com lint/typecheck/test.
  2. Rodar Parte 2 completa (Dockerfile, composes, .dockerignore, .hadolint.yaml).
  3. Rodar docker run --rm -i hadolint/hadolint < Dockerfile e mostrar a saída.
  4. Corrigir o que aparecer ou justificar via .hadolint.yaml.
  5. Commits separados:
    • chore: remove docs tooling (markdownlint, cspell, docs:*)
    • chore(docker): harden containers (no-new-privileges, non-root, chown)
Critério de aceite:
  • pnpm lint, pnpm typecheck, pnpm test passam.
  • Nenhum docs:* sobrou em package.json, CI ou README.
  • hadolint Dockerfile retorna exit 0 (ou apenas warnings justificados).
  • docker compose config e docker compose -f docker-compose.yml -f docker-compose.prod.yml config validam sem erro.
