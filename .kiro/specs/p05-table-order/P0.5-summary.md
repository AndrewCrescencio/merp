# P0.5 - Table Order Flow (openTable, closeTable, items CRUD)

## Implementação Concluída

### O que foi implementado:

1. **openTable**:
   - Cria order dinâmica do tipo `dine_in`
   - Set `current_order_id` na mesa
   - Usa `FOR UPDATE` lock para evitar race conditions
   - Retorna 400 se mesa já estiver aberta

2. **closeTable**:
   - Completa ou cancela a order vinculada
   - Libera `current_order_id` da mesa
   - Restaura status da mesa para `available`
   - Usa `FOR UPDATE` lock para evitar race conditions

3. **POST /api/v1/companies/{companyId}/orders/{orderId}/items**:
   - Adiciona itens a uma order aberta
   - Valida que product pertence à mesma location
   - Recalcula o total da order

4. **DELETE /api/v1/companies/{companyId}/orders/{orderId}/items/{itemId}**:
   - Remove itens de uma order aberta
   - Recalcula o total da order

5. **Order pode ficar aberta sem itens**:
   - Orders `dine_in` podem ser criadas sem itens iniciais
   - Recebem itens depois via endpoints acima

6. **Teste de Concorrência**:
   - Duas chamadas paralelas de open na mesma mesa
   - Só uma order é criada (lock FOR UPDATE)
   - Segunda chamada recebe 400

### Arquitetura:

**Repository criado:**

- `table-order-repository.ts` - Abertura/fechamento de mesa + items
