# P0.3 - Restaurant Table & Kitchen Station CRUD + Member Roles

## Implementação Concluída

### O que foi implementado:

1. **Restaurant Table CRUD**:
   - `GET /api/v1/companies/{companyId}/restaurant/tables` - Listar mesas (qualquer membro)
   - `POST /api/v1/companies/{companyId}/restaurant/tables` - Criar mesa (owner/manager)
   - `PATCH /api/v1/companies/{companyId}/restaurant/tables/{tableId}` - Atualizar mesa (owner/manager)
   - `DELETE /api/v1/companies/{companyId}/restaurant/tables/{tableId}` - Deletar mesa (owner/manager)
   - Unique constraint corrigida: `(company_id, location_id, number)` agora permite mesa 1 em múltiplas locations

2. **Kitchen Station CRUD**:
   - `GET /api/v1/companies/{companyId}/kitchen/stations` - Listar estações (qualquer membro)
   - `POST /api/v1/companies/{companyId}/kitchen/stations` - Criar estação (owner/manager)
   - `PATCH /api/v1/companies/{companyId}/kitchen/stations/{stationId}` - Atualizar estação (owner/manager)
   - `DELETE /api/v1/companies/{companyId}/kitchen/stations/{stationId}` - Deletar estação (owner/manager)

3. **Member List Endpoint**:
   - `GET /api/v1/companies/{companyId}/members` - Lista membros com role e defaultLocationId
   - Acesso: owner/manager apenas

4. **Roles Expandidos**:
   - Novos roles aceitos: `owner`, `manager`, `waiter`, `cashier`, `kitchen`
   - Constraint CHECK no banco: `company_member_role_check`

5. **Migration**:
   - `drizzle/0004_p03_restaurant_kitchen_members.sql` - Aplica todas as mudanças de schema

### Arquitetura:

**Repositories criados:**

- `restaurant-table-repository.ts` - CRUD de mesas
- `kitchen-station-repository.ts` - CRUD de estações

**Endpoints criados:**

- `server/api/v1/companies/[companyId]/restaurant/tables/`
- `server/api/v1/companies/[companyId]/kitchen/stations/`
- `server/api/v1/companies/[companyId]/members/index.get.ts`
