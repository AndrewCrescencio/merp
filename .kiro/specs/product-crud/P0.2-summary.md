# P0.2 - Minimal Product CRUD Implementation

## Implementação Concluída

### O que foi implementado:

1. **Repository de Produtos** (`server/utils/auth/company/product-repository.ts`):
   - `listProducts()`: Lista produtos ativos, filtrável por location
   - `createProduct()`: Cria produto com validação de preço e SKU único
   - `findProduct()`: Busca produto individual
   - `updateProduct()`: Atualiza produto com validação
   - `softDeleteProduct()`: Soft delete (isActive = false)

2. **Endpoints CRUD**:
   - `GET /api/v1/companies/{companyId}/products` - Listar produtos (qualquer membro)
   - `POST /api/v1/companies/{companyId}/products` - Criar produto (owner/manager apenas)
   - `PATCH /api/v1/companies/{companyId}/products/{productId}` - Atualizar produto (owner/manager)
   - `DELETE /api/v1/companies/{companyId}/products/{productId}` - Soft delete (owner/manager)

3. **Validações**:
   - unitPrice: `numeric(12,2)`, positivo, regex `/^\d+(\.\d{1,2})?$/`
   - SKU: único por empresa (constraint `product_company_sku_idx`)
   - name: obrigatório, 1-255 caracteres
   - locationId: obrigatório, UUID válido

4. **Autorização**:
   - Criado `assertCompanyRole()` e `assertCompanyMember()` em `authorization.ts`
   - Mutação: owner/manager apenas
   - Listagem: qualquer membro

5. **Testes de Integração** (`server/utils/auth/company/product.test.ts`):
   - Owner cria produto, waiter consegue listar
   - SKU duplicado na mesma empresa → rejeitado
   - SKU igual em empresas diferentes → permitido
   - Produto de outra empresa não aparece na listagem
   - unitPrice negativo/não numérico → rejeitado
   - Listagem com filtro de location

### Arquitetura existente aproveitada:

- Tabela `product` já existe com schema correto
- RLS policies já existem (0002_rls_policies_grants.sql)
- `withTenant()` para contexto RLS
- Middleware de tenant e auth já funcionais
